## 💡 提高需求质量的技巧

### 1. 使用结构化描述

❌ **不好**：
```
"有问题，不行"
```

✅ **好**：
```
**问题**：TTS播放按钮点击后无声音
**复现**：点击播放 → 按钮变灰 → 3秒后显示"无法播放"
**错误**：控制台显示 "enhancedVoices is not defined"
**环境**：Chrome 121, macOS 14.2
```

### 2. 提供证据而非猜测

❌ **不好**：
```
"可能是系统问题，因为我听不到声音"
```

✅ **好**：
```
"系统TTS测试正常（'say test'有声音），
但浏览器TTS无声音。控制台显示xxx错误。"
```

### 3. 说步骤而非现象

❌ **不好**：
```
"页面乱了"
```

✅ **好**：
```
"步骤：
1. 打开 http://localhost:8000/xxx.html
2. 点击播放按钮
3. 按钮变灰但无声音
4. 控制台显示错误"
```

## 🛠️ 诊断工具使用方法

### 方法1：直接在控制台运行
```javascript
// 1. 打开浏览器控制台（F12）
// 2. 复制 auto-diagnose.js 的内容
// 3. 粘贴到控制台
// 4. 按回车运行
// 5. 复制输出的JSON报告
```

### 方法2：保存为书签（推荐）
```javascript
// 创建一个书签，URL设为：
javascript:(function(){/* auto-diagnose.js 的内容 */})();

// 使用时直接点击书签即可运行诊断
```

## 🎓 从这次问题学到的经验

### 用户的教训
1. ✅ 信息要完整：不要只说"有问题"
2. ✅ 用工具诊断：不要猜测
3. ✅ 提供证据：截图、日志、JSON报告

### AI的教训
1. ✅ 不要猜测：基于事实分析
2. ✅ 全局修复：不要遗漏
3. ✅ 先诊断后修复：不要急着改代码

### 共同的教训
1. ✅ 建立标准：使用模板和工具
2. ✅ 双向反馈：及时确认理解
3. ✅ 持续改进：总结每次经验
